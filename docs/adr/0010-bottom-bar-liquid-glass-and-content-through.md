# 底栏三档效果（标准 / 液态玻璃 / 磨砂），内容穿底栏并引入 Backdrop 依赖

底栏可从设置页选三种效果，共用同一套**悬浮胶囊**版式（左右留边、全圆角、64dp 高），切换只换材质不重排版式：

- **标准**：不透明明快表面 + 选中胶囊底色，反馈走 M3 原生涟漪。不依赖任何着色器。
- **液态玻璃**：折射页面内容（`vibrancy` + `blur` + `lens`），**底栏本体与选中胶囊共用同一套配方**（边缘色散 + 45° 镜面高光 + 内缘压暗 + 外投影），按压时选中胶囊膨胀至约 1.36×。需 Android 13+。
- **磨砂**：半透明渐变面，同一套按压缩放，无着色器。AGSAL 不可用时的降级档，也是低版本设备的安全档。

三档都支持**点击切换**与**按住水平拖动切换**（胶囊跟手 + 速度拉伸 + 松手吸附，拖动跨格轻震）——见文末修订段。

**默认液态玻璃**；API < 33 时该项在设置页**置灰**并给出「需要 Android 13」说明，实际效果由纯函数解析为磨砂。

## 理由

ADR-0005 当年把 `RenderEffect` 高斯模糊列为「可选增强项」推迟（`radialGradient` 衰减已够柔和）。真机评估后发现：底栏是**唯一**同时满足「元素浮在内容之上」「面积小」「用户高频注视」三个条件的位置，玻璃在这里的收益远大于它带来的复杂度——这正好兑现 ADR-0005 留的那个口子，故视为该子决策的**部分采纳**，而非推翻。

为什么默认玻璃：维护者是本 App 唯一用户，已明确偏好玻璃观感（原型评估期的原话是「效果不错」）。三档共存则把「观感偏好」与「设备能力」两件事解耦——低版本设备自动落到磨砂，不必替用户猜。

为什么**不做**真水滴形与胶囊融合：用户描述的「长按导航条垂下一颗水珠」，实为官方 `LiquidBottomTabs` 的按压膨胀（`layerBlock` 缩放 + 高光 + 内阴影）。库能给的极限到此——`layerBlock` 只提供仿射变换，**没有非均匀形变（液化/拉长）**，`lens` 又硬性要求形状是 `CornerBasedShape` / `RoundedRectangularShape`（自定义 `Path` 用不了折射），且全库**没有** SDF smooth-union（metaball 粘连）。要那两样必须用 `runtimeShaderEffect` 从零写 AGSL，与「个人自用、维护成本最低」相悖，故不做。

为什么引入依赖：Backdrop（`io.github.kyant0:backdrop`，Apache-2.0）是评估过的成熟实现（3.5k+ star、活跃维护），且其 Android 变体转发到 androidx，**不与本项目 Compose 版本冲突**（`checkDebugDuplicateClasses` 通过），minSdk 声明为 21、不抬高本项目下限。自绘 AGSL 折射的可控性远低于用这个库。

## 代价（须知的边界）

1. **内容穿底栏**：玻璃必须有背景可折射，故内容延伸到屏幕底部、穿到底栏背后。这是本决策最大的结构改动——各 tab 屏须**为底栏留出底部空间**（现行做法：用 tab 屏外壳 `TabVerticalScrollColumn` / `TabLazyColumn` 自动叠加，见 `docs/conventions/edge-to-edge.md` §底栏穿透；**不能**用外层 padding，否则内容滚不到底栏背后、穿透失效）。二级页（练习会话、批次管理）不显示底栏，须自行避让手势条。
2. **原生崩溃风险**：库 FAQ 记录过 RenderThread `Fatal signal 11 (SIGSEGV)`。这类崩溃发生在 native 层，**Kotlin/Java 层 `catch` 不住**，因此「自动检测并降级」在技术上不可行。已记入 `pitfalls.md`；崩溃时用户可切回「标准」（设置存于 DataStore，不依赖渲染链路）。触发条件推测与「玻璃叠玻璃」的循环引用有关，本实现只做单层底栏、未使用 `exportedBackdrop`，暂未复现。
3. **设置页多一项**：底栏效果并入现有「外观」卡，与深色模式同为分段控件。
4. **玻璃强度不设档位**：不像 IT之家那样给「强/中/弱」多档，取一组调好的固定值（深浅色分别适配）。若日后需要，再加设置项，不改本决策结构。

## 边界

- **只做底栏**。卡片保持 ADR-0005 的不透明白底在光雾上悬浮，不被玻璃化。
- ~~**不做**按住底栏左右拖动切换 tab~~ → **已反转，见下方修订段**（2026-09-29）。
- **不做**选中胶囊折射图标本身（官方用了一层 `alpha=0` 的着色副本 + `combinedBackdrop`）：差异细微，省掉一层重复布局与合并 backdrop。
- **CONTEXT.md 不记录本决策**：这是 UI/实现词汇，不是业务领域词汇，与该文件「只放领域词汇」的定位一致。
- 底栏玻璃化**不外溢**到半模态解析面板与卡片；面板承载长文本，透明底会伤可读性（ADR-0007 的可读性约束优先）。

## 修订：支持按住拖动切换 tab（2026-09-29，反转上条边界）

### 新决定

底栏支持**按住水平拖动**切换 tab：胶囊跟手滑动、拖快时按速度拉伸（液滴感），**松手才吸附到最近 tab 并切换页面**；拖动跨过 tab 边界时轻震一次。三档（标准/磨砂/液态玻璃）**都支持**拖动——拖动是交互而非材质，与「三档统一版式」一致。

补充边界：

- **整条 bar 都可起拖**，不限定选中胶囊。官方只在胶囊上挂手势（胶囊跟手所以能一直拖），但胶囊仅占 1/4 宽度，按偏了就拖不动、而用户无从知道这个限制。
- **只接管水平**：横向位移先过触摸阈值才判为拖动，纵向占优则放手、原地弹回，不抢下层的纵向手势。
- **位移未过阈值算点击**，保留原有「点一下就切 tab」。
- **越界阻尼**：拖出两端时位移按 0.28 系数压缩，拖到头有阻力感而非硬停。
- **不做** `InteractiveHighlight`（官方那层追随手指的径向光晕，含一段 AGSL 着色器）：省一段着色器维护，观感差异有限。

### 为什么反转

维护者在真机上体验官方组件后明确要求这个交互（原话是「我还是想要按住了能够跟随手指在导航条上面滑动」）。这是「个人自用、审美与手感由维护者拍板」的直接体现，不需要更多论证。

### 同时纠正原边界里的错误理由

原边界写「底栏横向拖动手势会与页面内容（卡片流、列表横滑）争夺」——**这个理由是错的**，实测代码：

- 四个 tab 屏（练习配置/题库/统计/设置）**全部是纵向滚动**（`verticalScroll` / `LazyColumn`），没有任何横向手势；
- 全项目唯一的横向手势是练习会话页的 `HorizontalPager`，而**该页不显示底栏**（`showBottomBar` 只对一级 tab 路由为真）。

故「与内容争夺」在当前结构下不会发生。真正需要留意的是**最左 tab 距屏幕左缘约 20dp**（16dp `screenEdge` + 4dp 内边距），可能落入系统返回手势的触发区——这是**待真机验证**的风险，若实测冲突，备选是加大左右安全边距或限制边缘起拖。

### 实现备注

拖动状态机在 `ui/components/BottomBarDragState.kt`（职责参考官方 `DampedDragAnimation`，Apache-2.0），纯计算抽到 `BottomBarDragMath.kt` 并被单测覆盖（中间段必须严格线性、两端必须阻尼且不失控、拉伸取速度绝对值——最后一条曾写错导致往左拖变成收缩）。

## 修订二：选中态常驻玻璃感（2026-09-29）

### 问题

首版把**全部**玻璃塑形都挂在「按压进度」上：`progress = 0` 时只有一层 `accent 0.14` 的淡色块，`progress = 1` 才是（全透面层 + 镜面高光 + 内缘压暗 + 外投影 + 边缘色散 + 1.36× 膨胀）。

而 `progress` 只由「手指是否按在底栏上」驱动、**松手即归零**，于是松手后玻璃感整套消失、退回静态淡色块——维护者实测到「默认选中态与长按膨胀态不一致」，并明确要求滑动时也保持长按的那套高透观感。

### 新决定

**玻璃塑形改为常驻**，按压不再负责「从零开启玻璃」，两者职责重新划分：

| 状态 | 面层 | 高光/内阴影/外投影/色散 | 缩放 |
|---|---|---|---|
| 选中（未按下） | 极淡强调底 `accent 0.05`（可读性兜底） | **全部常驻** | 1.0 |
| 选中（按下/拖动中） | 同上 | 常驻基础上**轻微加强**（折射量 ×1.4、内阴影 ×1.25） | **1.36×** |

即：**按压只负责「鼓起」与「轻微加强」**，不再是玻璃的开光开关。松手后胶囊缩回 1.0，但高光与内阴影仍在，选中态本身看起来就是一块玻璃。

补充边界：

- **面层保留 `accent 0.05` 极淡底色**：全透虽最接近苹果观感，但背景花哨时「当前在哪个 tab」会不好认；0.05 几乎不损通透，却给可读性兜底。
- **未选中的三个 tab 保持素面**，不参与玻璃塑形（对比更强，一眼看出当前位置）。
- **磨砂档**无着色器，用「稍实强调底 + 一层 `accent 0.45` 亮描边」模拟玻璃边缘；**标准档不动**（它本就不走玻璃路线，仍是 M3 式胶囊底色）。

### 为什么

维护者是唯一用户、且对观感有明确要求（「我想滑动时也是长按膨胀的高透状态」）。此外这也修正了一处**设计上的不一致**：同一个选中态在「按住」与「松手」两种时刻呈现两套截然不同的视觉，本身缺乏理由——按压理应只是「受力反馈」，不该顺带决定「这块玻璃存不存在」。

## 修订三：底栏本体与选中胶囊共用同一套玻璃配方（2026-09-29）

### 问题

维护者实测反馈：**「色散效果、膨胀效果只有从『练习』Tab 长按或滑动才有完整的高透、色散等高级材质效果，其他 Tab 滑动就挺普通的」**。

### 根因

底栏有**两层独立材质**，两处配方不对称：

| 层 | `chromaticAberration` | `Highlight` | `Shadow` | `InnerShadow` |
|---|---|---|---|---|
| 选中胶囊 `CapsuleIndicator` | ✅ | ✅ | ✅ | ✅ |
| 底栏本体 `barMaterial` | ❌ **缺** | ❌ **缺** | ❌ **缺** | ❌ **缺** |

底栏本体当时只写了 `vibrancy() + blur(8dp) + lens(24dp, 24dp)`。底栏是四个 tab **常驻**的那一层，胶囊只在选中项处——于是观感变成「按住选中项才漂亮、其余时候普通」，用户自然会读成「只有某个 tab 有效果」。

### 排查过程中的两个已证伪假设（如实记录，防复发）

1. **`graphicsLayer.translationX` 导致 backdrop 采样错位**——曾据此把位移改成布局级 `offset`。事后轴向 A/B 测量（`offset` vs `graphicsLayer.translationX`）四槽位像素差 **+0.00**；通道互相关检测色散，四槽位峰值偏移均为 **0**（无通道错位）。**该假设不成立**。
2. **`press()` 的 `pressJob?.isActive` 幂等守卫吞掉了按压**——插桩显示冷启动与切换 tab 后 `busy=false → ACCEPT` 且 `prog` 都到 `1.0`。**该假设不成立**。

**教训**：本轮在像素测量上耗费远超收益，且前期测量协议本身有缺陷（`awaitTouchSlopOrCancellation` 把 `startX` 设在跨阈值的那次 MOVE 上，导致第一段位移不产生位移、逐槽标签全错）。**正确顺序应是：先做两处配方的静态逐项对照——这通常一眼定位——再考虑上像素测量。**

### 新决定

**底栏本体与选中胶囊共用同一套配方**：`vibrancy` + `blur` + `lens(chromaticAberration = true)` + `Highlight.Default` + `Shadow()` + `InnerShadow`。差异只允许出现在**尺度**上（底栏内缘压暗 `BAR_INNER_SHADOW = 10dp`，比胶囊的 8dp 略收敛——底栏面积大，半径过大会显脏）。

同时**保留布局级 `offset`**：它在 backdrop 2.0.1 上虽与 `graphicsLayer.translationX` 像素等价，但语义正确（`drawBackdrop` 依 `LayoutCoordinates` 采样），不依赖库的实现细节，是更稳的一侧。

### 为什么

维护者是唯一用户、对观感有明确要求。更本质的是：**底栏是常驻层，它的材质就是 App 的材质语言**。若只有选中胶囊带高级效果，等于把「材质」降格成「选中反馈」——这与修订二「玻璃塑形常驻」的结论直接冲突。

### 验证状态

- `.\gradlew.bat assembleDebug` → **BUILD SUCCESSFUL**
- `.\gradlew.bat testDebugUnitTest` → **97 个测试，0 失败**
- 底栏本体像素自参照差分（修复前 vs 修复后，练习页同位置）：**25.6% 像素改变**，平均亮度 243.8 → 240.2（内阴影压暗边缘，符合预期）
- 四个 tab 底栏本体亮度方差 777–989，**同一量级**（材质语言已一致）
- 维护者观感确认：**已确认无意见**（2026-09-29）

## 修订四：选中胶囊与底栏本体的环缝等厚（2026-10-01）

### 问题

选中胶囊嵌在底栏胶囊内，缝隙厚度不均：`CapsuleIndicator` 原先 `padding(horizontal = xs(4), vertical = sm(8))`，两个胶囊的端部半圆弧**不同心**——底栏本体高 64dp（端弧 R=32dp），选中胶囊高 64−2×8=48dp（端弧 r=24dp），但内弧圆心因左右 padding 偏移而错位 4dp。环厚（大圆半径 − 小圆半径的径向距离）沿弧线在 4~8dp 间游走：正左方向 4dp、正上下方向 8dp。维护者要求「圆环厚度（大圆半径 − 小圆半径）全局统一」。

### 新决定

选中胶囊四向 padding 统一取 `sm`(8dp)。数学上：**四向 padding 相等时内外胶囊端弧圆心自动重合**（外圆心 (32,32)，内圆心 (8+24, 8)=(32,32)），环厚处处相等 = 32 − 24 = **8dp**。上下缝维持原值 8dp（视觉变化最小），左右缝由 4dp 加深到 8dp；内胶囊高 48dp 不变，图标与文字不受挤压。

### 为什么

「同一块玻璃嵌在同一块玻璃里，缝应该一样宽」——不同心时环缝厚度随角度变化，视觉上是「歪的」，但肉眼只能感到不匀、说不出原因；同心后缝隙均匀，两层胶囊的关系安定。取 8dp 而非 4dp：8 是现状上下缝、改动面最小；若取 xs(4)，选中胶囊撑到 56dp 高，玻璃高光与内阴影的呼吸感会明显收窄。
