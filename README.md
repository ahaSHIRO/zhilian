# 知练 — Android 刷题 App 产品简报

## 产品目标

开发一款全新的 Android 刷题应用，面向维护者本人与同学使用（受众含新手同学，难度处理见 ADR-0011）。**定位是「碎片时间刷题」——单题应在等车、排队的间隙读完并作答完**，故题目**以基础/关键知识点为主**、篇幅受硬约束（见 [ADR-0016](docs/adr/0016-question-brevity-hard-limits-and-full-bank-reflow.md)）。题目可由 AI 根据只读的 Obsidian 笔记或允许的网络教程创作；电脑端经 AI 对抗复审、维护者验收后发布题目批次，Syncthing 将批次同步到手机，App 自动对账到手机本地题库，离线练习。

本项目独立开发，不修改 `<本地 Obsidian 库>` 或其中的笔记。Obsidian 是创作素材来源，不是应用题库或应用数据库。

## 已确认首版范围

- **平台**：Android 17 设备；Kotlin；Jetpack Compose；Room/SQLite；简体中文 UI；个人自用，APK 安装，包名 com.baiyin.zhilian；**竖屏锁定**（`screenOrientation="portrait"`）；依赖注入手动构造，不引入 DI 框架。
- **外观**：固定雾蓝配色（ADR-0005）+ 深色模式三态（跟随系统/浅色/深色）。底部导航栏三档效果可选——**标准 / 液态玻璃 / 磨砂**，默认液态玻璃；液态玻璃折射页面内容，**底栏本体与选中项共用同一套玻璃配方**（镜面高光 + 内缘压暗 + 边缘色散 + 外投影，故材质在任意 tab 下一致），按住选中项时像水珠一样鼓起（需 Android 13+，低版本该选项置灰并自动使用磨砂）。底栏支持**按住水平拖动切换 tab**（胶囊跟手、拖快时拉伸、松手吸附、跨格轻震），也保留点击切换。底栏是悬浮胶囊浮层、内容穿其背后，故各 tab 屏底部留白由页面自行处理。详见 ADR-0010。
- **项目起点**：创建独立的新项目。允许复用 GitHub 等来源的成熟开源组件；开发前评估活跃度、兼容性、维护风险与许可证义务，不为避免依赖而重复造轮子。
- **题目创作**：AI 可使用只读 Obsidian 笔记和菜鸟教程作为素材；使用其他网络来源前由维护者指定。出题代理（含外部新会话）的边界、标签词表与冷启动指引见 `docs/conventions/question-authoring.md` §七/§八。题目尽量原创改写，不大段复制来源文本。记录来源标题、链接及访问日期。AI 输出带格式版本、批次 ID、批次顺序号和题目 ID 的 JSON 文件；经 AI 对抗复审与维护者验收后放入 Syncthing 批次目录。首版不开发 AI 出题工具或电脑端批次编辑器。
- **正确性把关**：维护者正是本题库的学习者，不具备判断答案对错的能力，故**正确性不由人工判断**——原「人工审核」改为「复审 + 验收」两道：**复审**由未参与出题的代理冷启动完成（不接触答案与解析独立作答，再核验答案唯一性、干扰项质量、解析自证性与来源有效性），**验收**由维护者做体感判断（看得懂、深浅合适、**篇幅适合碎片时间**；同一考点可变式多考但考法不得雷同）并保留一票否决。解析采用教材式写法（前置概念、易错点、变体提示）。详见 ADR-0006。
- **解析深度**：解析分「必写 + 按需」两级——必写「为什么对」与「为什么错」；「前置概念/常见误解/变体提示」仅在确实有价值时写，不灌水。简单题 150–300 字，**硬上限 400 字**（2026-10-05 定，见出题规范 §三 篇幅硬线）。概念题的 `source` 必须指向**可独立核实的权威材料**（官方文档 / JDK 源码 / 一手文献，四档见出题规范 §三「source 四档」）以便核验。解析以半模态面板展示（ADR-0007），可滚动，不受卡片高度限制。
- **题型**：单选、多选、判断、单空填空。填空题可有多个可接受答案，用户答案经 **Unicode NFC 归一化 + 去首尾空白**后区分大小写精确匹配。
- **题目组织**：当前支持 Kotlin、Java 与面试（interview）三个科目（Schema 另预留 ArkTS 占位）；分类为单层结构且挂在科目下（不同科目的同名分类互不干扰），另有标签。题目支持纯文字 Markdown 内容（首版不含图片）、代码块和离线语法高亮（代码块按卡片宽度软换行渲染，不用横向滚动，避免长行被卡片流手势吞掉）。每题包含答案、解析及来源信息。
- **内容配比与篇幅**：每批「概念题」（无代码）**≥ 90%**、「程序题」（含可运行代码）**≤ 10%**（20 题批最多 2 道、15 题批最多 1 道）。**篇幅硬线（全库适用）**：题干去代码 ≤100 字、单题代码块 ≤1 个且 ≤6 行、题干含代码 ≤180 字、解析 ≤400 字、单个选项 ≤60 字。内容取向**以基础/关键知识点为主**——定义/名词型题**允许**（原「排除名词背诵型」作废），仅排除只问数量/只考拼写等无信息量凑数题。难度梯度软约束不变：每批宜含 2–3 道入门题铺难度坡度，程序脑内执行题不宜连续超过 2 道（ADR-0011）。**2026-10-05 全库改定**：存量 26 批已按此口径全量重排达标，新批同口径（[ADR-0016](docs/adr/0016-question-brevity-hard-limits-and-full-bank-reflow.md) + 出题规范 §三）。
- **批次与变式**：一批对应一个笔记（或强相关知识点），常态 10–15 题、核心知识单元 15–20 题；考点分核心/一般两级，核心考点出 2–4 道变式反复考查——变式须换题型、换角度或换场景，仅改数字与措辞的伪变式禁止；跨批次允许对已考考点间隔复考。同一考点的不同考法不算重复，题干雷同才算。
- **同步与导入**：Syncthing 仅同步 JSON 批次，不同步 SQLite 数据库或练习记录。App 通过系统文件选择器获得用户所选同步目录的持久访问授权。**电脑端是题库权威源**：App 每次回到前台自动对目录做一次**题库对账**——新增尚未入库的题，并以同一 `questionId` **原位覆盖**已入库题的内容（分类/标签/顺序号等按文件覆盖，作答历史与掌握度随题目身份保留）；只增与更新，**不因目录中文件被移走而删除本机题**。有变更时在「设置 → 批次导入」页留一条对账摘要（平时不弹）。Schema 失败、批内 ID 重复、顺序号冲突的批次进「待处理」并给原因、下次自动重试；疑似重复仍人工裁决。目录文件与已处理记录按批次顺序号**倒序**展示；保留「立即对账」手动按钮，以及**仅对新批次开放**的单个导入兜底。**不做 App 未打开时的后台静默入库**（[ADR-0017](docs/adr/0017-directory-authoritative-reconciliation.md) / ADR-0008）。
- **导入韧性**：逐题校验；有效题对账入/更新，无效题跳过并报告具体原因。部分成功仍记录批次处理状态；修正原批次后，下次前台对账自动重试。不同 ID 但内容疑似相同的题目标记出来，等待人工选择导入或跳过。格式版本不兼容时不导入并说明原因。**同一 `questionId` 的内容会按目录原位更新**（ADR-0017），不再像旧模型那样一律跳过。
- **题目生命周期**：出题侧按「新 ID」表示修订（不原位改已发布题）；但在本机题库层面，**题库对账允许对同一 `questionId` 的原位内容刷新**（ADR-0017），本地作答历史与掌握度随身份保留。题目不物理删除——唯一的删除路径是手动**「撤销批次导入」**（整批删题并级联清除该批作答记录与收藏）。后续批次可停用既有题目；停用不可恢复，停用题不出现在新练习中，但保留历史作答并计入历史统计。**另一例外**：「全库一次性重排」——对整个题库口径做一次性改定时，允许原位重写已投放批次并配一次清库重导（[ADR-0016](docs/adr/0016-question-brevity-hard-limits-and-full-bank-reflow.md) + 出题规范 §六；本次 `batch-0001~0026` 即此例外）。
- **练习**：顺序或随机练习；**选项打乱**开关（默认开）——单选/多选的选项行序按题目身份稳定重排，同一道题在任何会话中顺序一致，字母标号跟内容走，判分与显示位置无关，判断/填空不受影响；**题量**可选（10–100、步长 5、默认 20，半模态面板滑块选择）。一题一卡、左右滑动切换（ADR-0003；**一屏只呈现本题卡片**，不露相邻卡边缘），末页为会话小结卡；提交后卡片内给出正误横幅，**双击卡片**升起半模态解析面板（ADR-0007；默认全屏、短解析也不露白，下拉或点遮罩关闭），滑到下一题自动收起。可跳过，跳过不记作答。返回（手势/按键）播放经典水平侧滑**直接退出会话、无确认弹框**（预测性返回已停用，ADR-0009）。单次练习不重复出题；题目不足时练习现有题目，不重复补足。练习中关闭 App 后不恢复当前会话，但已提交的作答保留；**配置变更（系统深浅色、字体与显示大小、语言）不算离开，会话不中断**。
- **筛选**：科目、分类、标签、题型、错题、收藏等条件可组合（标签在选定分类后作为更细一层收窄），结果必须满足所有已选条件。顺序模式按批次顺序号及批次文件内顺序排列，后续批次追加在后。练习配置页为两张语义分组卡：**筛选条件卡**（各维度 + 符合条件的题目数尾行）与**会话设置卡**（顺序/选项打乱/题量/开始练习）。
- **评分**：单选与判断按标准答案判定。多选得分为 `max(0, 正确选中数 - 错误选中数) / 正确选项总数`；只有满分记为答对。填空按已定义的精确匹配规则判定。每次练习结束时在结尾卡显示**会话得分**（满分 100 按题数均分，各题按得分率折算，跳过计 0 分；仅会话内展示，不进历史统计）。
- **错题与统计**：错题按题目跨练习累计连续全对两次后移出；答错重置连续正确数，跳过不影响。部分分计入统计但不算全对，不推进连续正确数。显示首次作答正确率、全部作答正确率、多选全对率和平均得分率，另有**弱项卡**（当前错题数与错误最集中的分类 TOP3，指向"哪里弱练哪里"）；停用题历史尝试继续计入历史统计。
- **记录**：题库、练习作答、收藏和统计保存在手机本地。可清除全部本机练习记录；首版不提供练习记录备份、导出或跨设备同步。无账号、提醒、每日打卡或模拟考试。
- **网络边界**：App 本身完全离线，不连接局域网服务器或互联网；文件同步由 Syncthing 负责。

## 首版不包含

多空填空、考试模式、题目编辑器、AI 出题工具、题库数据库文件同步、进度数据同步/备份、账户与多用户、提醒或打卡、任意网络源自动抓取、**按目录删除题**（文件被移走不动本机题；删除只走手动「撤销批次导入」）。

## 已知缺陷与刻意不做（2026-09-30 架构评审后）

以下三项是**已确认存在、本轮刻意不改**的边界。别再当「未完成的待办」重开，也别在下次评审里重新当成新发现：

- **退出页面会静默取消在途的写操作**（提交作答、批次导入）：写操作跑在页面作用域里，退出即取消（Room 事务回滚，不损坏数据，但用户看不到「这次没提交」）。要根治需引入 Application 级作业容器承接「已确认的写操作」，是独立课题；当前窗口是毫秒级，代价不划算。
- **底栏不参与二级页转场**：进入/退出二级页时底栏瞬间显隐，不随 300ms 侧滑编排。要改需把它纳入转场并把玻璃层与 z 序一起重排（碰 ADR-0010），属纯观感问题。
- **系统返回键连按不拦**：会话页连按返回会先退会话再退 App。只守页面上的按钮（见 `ui/navigation/PracticeNavigation`），不重开页面级 BackHandler —— 那会与 ADR-0009 冲突。

## 核心流程

1. AI 基于获准素材生成一个带唯一 ID 和批次顺序号的 JSON 批次；经 AI 冷复审（必要时含代码运行验证）与维护者验收定稿后，保存到 Syncthing 同步目录。
2. Syncthing 将已定稿批次同步至手机。
3. App 每次回到前台自动对批次目录做**题库对账**：新增未入库题、按同一 `questionId` 更新已入库题的内容，并统一执行停用；问题批次进「待处理」、疑似重复待人工裁决。批次页留一条对账摘要，也可手动「立即对账」或对全新批次用单个导入兜底。
4. 用户在本机筛选并练习；题库和作答记录均可离线使用。

## 开源依赖原则

优先评估成熟、维护活跃、适配 Kotlin/Android 的开源组件，特别是数据库访问、Markdown 呈现、代码高亮和 JSON 校验。每项依赖在引入前记录其用途、版本、许可证及许可证义务；遵守署名、NOTICE、源码提供或再分发等适用要求。不要仅因在 GitHub 可见就假定可自由使用，也不要引入与首版离线和维护目标不符的重型依赖。

## 待实现时确认

- 最低 Android API：主力机已核实为 Android 17（API 37，小米 25060RK16C）。发布定案 minSdk=37；当前工程 minSdk 暂保持 31 以兼容 MuMu 模拟器（Android 15）联调，发布前收回。
- JSON 批次格式已定案 v1（2026-09-27；2026-09-28 修订 `subject` 枚举扩为 kotlin / java / arkts，ArkTS 为占位；2026-09-29 扩入 `interview` 面试科目）：Schema 与规格见 docs/schema/（字段、枚举、约束、版本迁移策略、应用级校验清单）。出题端按此生成，App 导入前逐题校验。
- 疑似重复判定：方法已定为题干 NFC+trim 归一化精确相同且 ID 不同（见 docs/schema/batch-spec-v1.md）；导入页提供逐条人工裁决对话框（新题与已有题并排，选导入或跳过），批量导入不绕过该裁决。
- 科目/标签身份规范已定案 v1：科目为 Schema 枚举小写代码（当前为 `kotlin`、`java`、`interview`，另有 `arkts` 占位）；分类名字即身份（科目内 NFC+trim 精确匹配），不同科目的同名分类互不干扰；标签建议全小写、区分大小写。
- 第三方依赖核查（2026-09-27 已完成；2026-09-29 补底栏玻璃）：Markdown 渲染与代码高亮用 multiplatform-markdown-renderer（Apache-2.0，含 -m3/-code 模块，纯文字无需图片模块）；批次 JSON Schema 校验用 networknt json-schema-validator 2.x Android 兼容线（Apache-2.0）；JSON 解析用 kotlinx-serialization；**底栏液态玻璃**用 io.github.kyant0:backdrop 2.0.1 + io.github.kyant0:shapes 1.2.1（均 Apache-2.0；backdrop 为 Compose Multiplatform 构件，Android 变体转发 androidx，已用 `checkDebugDuplicateClasses` 验证不与本项目 Compose 版本冲突，AAR 声明 minSdk 21 不抬高本项目下限；shapes 必须显式声明，因其在 backdrop 内仅为 runtime 依赖）；Markwon/prism4j/compose-richtext 已核实排除（停更或 alpha）。均为 Apache-2.0/MIT，义务限于保留版权与 NOTICE。引入时以当时最新稳定版复核。

## 电脑端工具

- `tools/batch-check.py`：批次 JSON 预校验（Schema + 应用级规则 + 跨批次重复 + 标签词表拦截）
- `tools/bank-stats.py`：题库存量盘面报告（科目/分类/题型/标签/来源/程序题占比）
- 两者从环境变量 `ZHILIAN_BATCHES_DIR` 读取本机批次目录（未设置时回落当前目录，可用 `--batches-dir` 显式指定）；标签词表由 `tools/vocab.py` 自 [docs/conventions/question-authoring.md](./docs/conventions/question-authoring.md) §八 实时解析，文档登记即生效
