# 知练 — Android 刷题 App 产品简报

## 产品目标

开发一款全新的 Android 刷题应用，首发面向个人使用。题目可由 AI 根据只读的 Obsidian 笔记或允许的网络教程创作；电脑端经 AI 对抗复审、维护者验收后发布题目批次，Syncthing 将批次同步到手机，App 导入到手机本地题库，离线练习。

本项目独立开发，不修改 `<本地 Obsidian 库>` 或其中的笔记。Obsidian 是创作素材来源，不是应用题库或应用数据库。

## 已确认首版范围

- **平台**：Android 17 设备；Kotlin；Jetpack Compose；Room/SQLite；简体中文 UI；个人自用，APK 安装，包名 com.baiyin.zhilian；依赖注入手动构造，不引入 DI 框架。
- **项目起点**：创建独立的新项目。允许复用 GitHub 等来源的成熟开源组件；开发前评估活跃度、兼容性、维护风险与许可证义务，不为避免依赖而重复造轮子。
- **题目创作**：AI 可使用只读 Obsidian 笔记和菜鸟教程作为素材；使用其他网络来源前由维护者指定。题目尽量原创改写，不大段复制来源文本。记录来源标题、链接及访问日期。AI 输出带格式版本、批次 ID、批次顺序号和题目 ID 的 JSON 文件；经 AI 对抗复审与维护者验收后放入 Syncthing 批次目录。首版不开发 AI 出题工具或电脑端批次编辑器。
- **正确性把关**：维护者正是本题库的学习者，不具备判断答案对错的能力，故**正确性不由人工判断**——原「人工审核」改为「复审 + 验收」两道：**复审**由未参与出题的代理冷启动完成（不接触答案与解析独立作答，再核验答案唯一性、干扰项质量、解析自证性与来源有效性），**验收**由维护者做体感判断（看得懂、深浅合适、不重复）并保留一票否决。解析采用教材式写法（前置概念、易错点、变体提示）。详见 ADR-0006。
- **解析深度**：解析不止给正确答案，需讲清"为什么错"、铺垫该题依赖的前置概念、点出常见误解，并给变体提示（"把 X 换成 Y 会怎样"）。这是学习向定位，不改批次格式。
- **题型**：单选、多选、判断、单空填空。填空题可有多个可接受答案，用户答案去除首尾空白后进行区分大小写的精确匹配。
- **题目组织**：首发 Kotlin 科目；分类为单层结构，另有标签。题目支持纯文字 Markdown 内容（首版不含图片）、代码块和离线 Kotlin 语法高亮。每题包含答案、解析及来源信息。
- **同步与导入**：Syncthing 仅同步 JSON 批次，不同步 SQLite 数据库或练习记录。App 通过系统文件选择器获得用户所选同步目录的访问授权；启动时及手动检查新批次，显示待处理项，由用户确认导入。批次文件保留，App 记录已处理批次，避免重复处理。
- **导入韧性**：逐题校验；有效题导入，无效题、已有题目 ID 跳过并报告具体原因。部分成功仍记录批次处理状态；修正原批次后可重试，只补入此前失败的题，已导入 ID 继续跳过。不同 ID 但内容疑似相同的题目标记出来，等待人工选择导入或跳过。格式版本不兼容时不导入并说明原因。
- **题目生命周期**：首版只追加，不原位覆盖或删除已发布题目；修订内容视为新题并使用新 ID。后续批次可停用既有题目；停用不可恢复，停用题不出现在新练习中，但保留历史作答并计入历史统计。
- **练习**：顺序或随机练习；一题一屏；提交后立即显示正误、正确答案和解析。可跳过，跳过不记作答。单次练习不重复出题；题目不足时练习现有题目，不重复补足。练习中关闭 App 后不恢复当前会话，但已提交的作答保留。
- **筛选**：科目、分类、标签、错题、收藏等条件可组合，结果必须满足所有已选条件。顺序模式按批次顺序号及批次文件内顺序排列，后续批次追加在后。
- **评分**：单选与判断按标准答案判定。多选得分为 `max(0, 正确选中数 - 错误选中数) / 正确选项总数`；只有满分记为答对。填空按已定义的精确匹配规则判定。
- **错题与统计**：错题按题目跨练习累计连续全对两次后移出；答错重置连续正确数，跳过不影响。部分分计入统计但不算全对，不推进连续正确数。显示首次作答正确率、全部作答正确率、多选全对率和平均得分率；停用题历史尝试继续计入历史统计。
- **记录**：题库、练习作答、收藏和统计保存在手机本地。可清除全部本机练习记录；首版不提供练习记录备份、导出或跨设备同步。无账号、提醒、每日打卡或模拟考试。
- **网络边界**：App 本身完全离线，不连接局域网服务器或互联网；文件同步由 Syncthing 负责。

## 首版不包含

多空填空、考试模式、题目编辑器、AI 出题工具、题库数据库文件同步、进度数据同步/备份、账户与多用户、提醒或打卡、任意网络源自动抓取、题目修改覆盖与物理删除。

## 核心流程

1. AI 基于获准素材生成一个带唯一 ID 和批次顺序号的 JSON 批次；经 AI 冷复审（必要时含代码运行验证）与维护者验收定稿后，保存到 Syncthing 同步目录。
2. Syncthing 将已定稿批次同步至手机。
3. App 检查并展示批次，用户确认后逐题校验；有效题进入本机题库，问题项与疑似重复项清晰报告/待决。
4. 用户在本机筛选并练习；题库和作答记录均可离线使用。

## 开源依赖原则

优先评估成熟、维护活跃、适配 Kotlin/Android 的开源组件，特别是数据库访问、Markdown 呈现、代码高亮和 JSON 校验。每项依赖在引入前记录其用途、版本、许可证及许可证义务；遵守署名、NOTICE、源码提供或再分发等适用要求。不要仅因在 GitHub 可见就假定可自由使用，也不要引入与首版离线和维护目标不符的重型依赖。

## 待实现时确认

- 最低 Android API：主力机已核实为 Android 17（API 37，小米 25060RK16C）。发布定案 minSdk=37；当前工程 minSdk 暂保持 31（Material You 最低线）以兼容 MuMu 模拟器（Android 15）联调，发布前收回。
- JSON 批次格式已定案 v1（2026-09-27）：Schema 与规格见 docs/schema/（字段、枚举、约束、版本迁移策略、应用级校验清单）。出题端按此生成，App 导入前逐题校验。
- 疑似重复判定：方法已定为题干 NFC+trim 归一化精确相同且 ID 不同（见 docs/schema/batch-spec-v1.md）；导入确认界面细节待实现时定。
- 科目/标签身份规范已定案 v1：科目为 Schema 枚举小写代码（当前仅 kotlin）；分类名字即身份（科目内 NFC+trim 精确匹配）；标签建议全小写、区分大小写。
- 第三方依赖核查（2026-09-27 已完成）：Markdown 渲染与代码高亮用 multiplatform-markdown-renderer（Apache-2.0，含 -m3/-code 模块，纯文字无需图片模块）；批次 JSON Schema 校验用 networknt json-schema-validator 2.x Android 兼容线（Apache-2.0）；JSON 解析用 kotlinx-serialization；Markwon/prism4j/compose-richtext 已核实排除（停更或 alpha）。均为 Apache-2.0/MIT，义务限于保留版权与 NOTICE。引入时以当时最新稳定版复核。
